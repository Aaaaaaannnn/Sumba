# V0.20 — Autenticação real (piloto isolado)

## O que está implementado
- Email + palavra-passe, confirmação OTP, login OTP sem criação implícita de conta, recuperação por OTP e redefinição de palavra-passe, reenvio com cooldown de 60 s no cliente (rate limit real é do servidor), logout global após alteração via recuperação.
- OAuth Google e Facebook em PKCE; métodos vinculados via getUserIdentities e linkIdentity (manual linking depende de configuração Supabase); sem pedir dados sociais adicionais.
- Perfis, bancada, empresa e avatar usam a fundação RLS V0.12. Nenhuma sessão real entra no ADM demo ou obtém privilégios. Sem migração das encomendas ou do catálogo.
- Worker separado de assets apenas de public/real, configuração restrita a https://zunga-auth.stivenluanda04.workers.dev (URL planeada, ainda não confirmada). A origem do marketplace não pode inicializar o SDK; não colocar HTML demo no Worker de autenticação. CSP, no-store, noindex, proteção de framing. SDK CDN fixado 2.119.0 já usado em V0.12, bundle local auditado recomendado antes do lançamento.
- Modelos de emails em supabase/auth-templates/ (não contêm segredos). O código usa apenas a publishable key.

Se o subdomínio workers.dev real for diferente, actualizar public/real/config.js com a origem exacta antes do deploy. Verificar resposta dos headers e que o Worker só serve a área de autenticação.
2. Supabase Zunga: https://supabase.com/dashboard/project/asxyjhaujsowmdrpkcqc/auth/url-configuration — Site URL e Redirect URLs = a origem confirmada com / final. Sem wildcards e sem origem demo.
3. Authentication > Sign In / Providers > Email: activar email, exigir confirmação, desactivar anonymous sign-ins. Palavra-passe mínima 12, OTP de seis dígitos, expiração recomendada 600 s; configurar rate limits no servidor. Não desactivar confirmação para contornar SMTP. Validar parâmetros no painel real.
4. Authentication > Email Templates: copiar HTML de confirm-signup.html (Confirm signup), magic-link.html (Magic link / OTP), recovery.html (Reset password). Cada um usa {{ .Token }}, não links. Assuntos respectivamente: Confirma a tua conta ZUNGA; Código de acesso ZUNGA; Recupera o acesso à ZUNGA. Activar notificações de segurança disponíveis (por exemplo Password changed) e usar password-changed.html onde aplicável. Testar cada modelo. SMTP predefinido envia apenas a membros autorizados da equipa; público exige SMTP próprio, remetente verificado e limites. Configurar host, porta, utilizador, password, nome/email do remetente directamente no Dashboard. Preferir domínio próprio e SPF/DKIM/DMARC. Desactivar tracking de links se houver. Não publicar passwords ou chaves.
